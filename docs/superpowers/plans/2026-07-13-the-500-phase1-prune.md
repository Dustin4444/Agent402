# The 500 — Phase 1 (Prune) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the 970 generated pairwise `convert-*` tools with zero capability loss (parametric `unit-convert` absorbs their full unit table), gracefully retire the old routes, and land the interim catalog at 462 — WITHOUT deploying an interim number to prod.

**Architecture:** `src/tools/convert-gen.js` currently `generate()`s 970 tool objects from a 13-category unit table and exports `CONVERSIONS` (mounted in server.js). We invert it: the file becomes the unit-table module (exports `UNIT_CATEGORIES`, no tools); kit2's `unit-convert` consumes the FULL table (12 linear categories + temperature special-case); server.js unmounts `CONVERSIONS` and adds a 410-teaching handler for the dead API routes + a 301 for the dead tool pages.

**Tech Stack:** Node/Express, plain JS, offline assertion-script tests.

## Global Constraints

- **DEPLOY POLICY (overrides the usual flow): every Phase 1–3 push uses `[test]` ONLY — never `[deploy]`.** Prod stays at 1,432 until the single atomic v2.0.0 launch deploy. If prod needs an urgent hotfix mid-overhaul, cherry-pick the fix to a temp branch cut from `main` — do not deploy this branch.
- Zero capability loss: every unit pair the 970 tools converted must answer via `POST /api/unit-convert` (same math, temperature offsets included).
- Dead API routes return **410 Gone** with a JSON body teaching the replacement (never 301 a paid POST). Dead `/tools/convert-*` pages **301** → `/tools/unit-convert`.
- The `conversion`-category format tools (json-to-csv, yaml-to-json, openapi-*, …) and `timezone-convert`, `base-convert`, `roman` are NOT part of the prune — only slugs generated by convert-gen.
- After the prune run `node scripts/sync-count.js` (1,432 → 462) and commit its sweep.
- No CI markers in task commits; the controller adds `[test]` on push batches.
