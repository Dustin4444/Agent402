# "The 500" — catalog overhaul design

**Status:** Draft for owner review.
**Date:** 2026-07-13
**Owner:** Havok Holdings LLC

## Thesis

The catalog's headline number (1,432) is 68% pairwise unit-conversion permutations that
no agent has ever organically bought and that a parametric tool (`unit-convert`) already
covers. The overhaul replaces inflation with curation — and makes curation the product:

> **Exactly 500 catalog entries — 400 tools + 100 skill packs — CI-enforced.
> For a new tool to enter, one must leave. Every entry answers its own example,
> is priced to market, and has settled real USDC on-chain.**

The cap is permanent policy (owner-approved): the number stops being a metric and
becomes a promise. Launch as **v2.0.0**.

## Decisions (locked with owner)

1. **Count semantics:** 500 TOTAL catalog entries = 400 tools + 100 skill packs.
2. **Hard cap:** CI fails unless tools == 400 and packs == 100 exactly. One-in-one-out.
3. Everything must keep working end-to-end: full example sweep, canary, prod verify,
   PageSpeed bar (Perf 99/A11y 100/BP 100/SEO 100) all hold.

## The math

- Today: 1,432 entries (1,340 tools + 92 packs).
- Prune: −970 pairwise `convert-*` tools (generated by `src/tools/convert-gen.js`) →
  462 entries (370 tools + 92 packs).
- Build: +30 tools (→400) and +8 skill packs (→100) → **exactly 500**.
- Kept, explicitly: `unit-convert` (parametric, covers all 970), `timezone-convert`,
  the `conversion`-category tools that are NOT pairwise permutations (currency/fx and
  friends hit live data), and today's `evm-rpc`.

## Phase 1 — Prune (its own PR)

- Remove the 970 pairwise tools from `convert-gen.js` (keep any non-pairwise exports;
  verify what else the module provides before deleting).
- **No 404 graveyard:** `/tools/convert-<x>-to-<y>` pages 301 → `/tools/unit-convert`.
  The API routes `POST /api/convert-<x>-to-<y>` return **410 Gone** with a JSON body
  pointing at `POST /api/unit-convert` and the exact input shape — agents that cached
  the old route learn the replacement in one call. (410, not 301: agents must not
  silently re-POST paid calls across routes.)
- Cleanups: `src/find.js` ranking corpus, category pages, `scripts/test-all.js`
  expectations, any convert-specific tests, POW_SLUGS interactions (converters were
  PoW-eligible), Bazaar entries go stale and self-heal (no dereg API).
- `node scripts/sync-count.js` at the new interim count so CI stays green mid-project.

## Phase 2 — Build to the numbers (its own PR, possibly split)

**Selection is demand-driven, not invented.** Source the +30 tools / +8 packs from:
1. The wish/find-miss log (`recordWish` data — what agents ASKED for and we lacked).
2. The 2026-07-13 deep-dive gaps: micro-feeds (evm-rpc siblings, e.g. token metadata,
   nonce/receipt helpers), enrichment (company/domain), live-data finance/macro
   extensions, image/media capabilities within our existing upstreams.
3. Explicitly OUT of scope: session/streaming STT (own project — needs its own spec),
   video generation (upstream cost/risk needs separate evaluation), anything without a
   deterministic, example-answerable implementation.

**Quality bar per tool (non-negotiable):** deterministic handler; answers its own
documented example against the real upstream; priced to market (competitor table from
the deep dive); egress tools in `WALLET_ONLY_SLUGS`; covered by a kit test; buyable by
the paid canary. Packs: composed from existing tools, each pack runs end-to-end in the
skill-pack CI check.

**Gate:** the shortlist (30 tools + 8 packs, one line each with price + demand evidence)
is presented to the owner for approval BEFORE implementation.

## Phase 3 — The invariant (CI cap)

- `scripts/sync-count.js --check` (already in CI) extended: assert
  `tools === 400 && packs === 100` — any drift fails the build with a message that
  states the policy: "The catalog is capped at 500 (400 tools + 100 packs). For a new
  tool to enter, one must leave."
- Policy documented in README, wiki, CLAUDE.md conventions, and the /marketplace +
  homepage copy.

## Risks / mitigations

- **SEO:** 970 thin pages disappear → net positive (doorway-page risk removed); 301s
  preserve any stray equity; sitemap regenerates.
- **Buyers of removed routes:** PostHog shows ~zero organic converter buys; the 410
  body teaches the replacement; the sweep burner is ours.
- **Count drift mid-project:** each phase ends with sync-count at the true interim
  number; the hard gate lands only when 500 is real.
- **Rushed additions re-creating filler:** the owner-approved shortlist + the quality
  bar + canary-buyable requirement are the guard.

## Execution

Subagent-driven (fresh implementer per task + task review + final whole-branch review),
same discipline as the marketplace merge. Phases land as separate PRs in order; each
leaves prod green. Estimated shape: Phase 1 is one large mechanical PR; Phase 2 is the
long pole (30 tools at the quality bar); Phases 3–5 are small and fast.
